# Codex

このディレクトリは、ホストマシンの `$HOME/.codex` のリンク元である。
ディレクトリ全体をリンクすることで、`$HOME/.codex` をバインドマウントする
コンテナから、この dotfiles リポジトリ内の `AGENTS.md` などを参照できるようにする。

## 配置方法

配置スクリプトは、既存の `$HOME/.codex` を移動、統合、上書き、または
バックアップしない。ホストマシン上のファイル移動は利用者の責任で行う。

1. `$HOME/.codex` を使用しているコンテナと Codex のプロセスを停止する。
2. 既存の `$HOME/.codex` から必要なファイルをこのディレクトリへ移動する。
3. 既存の `$HOME/.codex` ディレクトリを移動または削除する。
4. このディレクトリで以下を実行する。

   ```sh
   ./deploy.sh
   ```

5. 新しいシンボリックリンクを基にバインドマウントされるよう、コンテナを
   再作成または再起動する。

配置後の構成は以下のとおりである。

```text
$HOME/.codex -> $HOME/dotfiles/root/.codex
```

## 厳格な `.gitignore` の方針

Codex はこのディレクトリに、認証情報、会話履歴、セッションデータ、シェルの
スナップショット、ログ、キャッシュ、SQLite データベース、プラグインなど、
マシン固有または機密性のある状態を書き込む可能性がある。そのため、
`.gitignore` は原則拒否の方針を採用する。`*` ですべてのパスを無視し、
内容を確認した dotfiles だけを明示的に許可する。

既知の生成ファイルだけを列挙する方式へ変更してはならない。Codex の更新により、
現時点では不明な名前の状態ファイルが追加される可能性がある。管理対象のファイルや
ディレクトリを追加するときは、可能な限り限定的な `!` ルールを追加し、
コミット前にステージされたファイルを確認する。

```sh
git status --short
git diff --cached --name-only
```

認証情報、履歴、セッション、ログ、データベース、キャッシュ、一時ファイルは
決して許可しない。非公開リポジトリであっても、秘密情報やマシン固有の状態を
リポジトリへ含めない。
